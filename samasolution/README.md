# Sama Solutions — website + admin panel

A production-grade, server-rendered website for **Sama Solutions** (New Delhi) with a separate
admin panel, a Pan-India / international market-area engine, and generated SEO for every page.

Live target: `https://www.samasolution.in`

---

## 1. Stack

| Layer | Choice |
| --- | --- |
| Runtime | Node.js 22 (uses the built-in `node:sqlite`) |
| Server | Express 4 |
| Templates | EJS — server-rendered HTML, no client-side framework |
| Database | SQLite at `data/site.db` (auto-created and seeded on first boot) |
| Styles | Hand-written CSS (`public/css/site.css`, `public/css/admin.css`) |
| Icons | 48 original monochrome SVG icons in `src/icons.js` |
| Images | Original black-and-white compositions in `public/img/` |
| Uploads | `multer` → `public/uploads/` |
| Fonts | Self-hosted: Inter Tight (variable) + Instrument Serif |

No CDN, no analytics by default, no third-party scripts. The whole site ships from one process.

## 2. Run it

```bash
cd samasolution
npm install
npm start            # http://localhost:3000
```

The database seeds itself the first time the server starts. To rebuild it from scratch:

```bash
npm run seed         # wipes and re-inserts all demo content
npm test             # 24 tests: unit + full HTTP sweep
```

Environment variables (all optional):

```
PORT=3000
DB_FILE=/absolute/path/to/site.db
```

## 3. Admin panel

The panel is mounted separately at **`/admin`** and is `noindex, nofollow`. It is not linked from
the public site.

```
URL       http://localhost:3000/admin/login
Email     admin@samasolution.in
Password  Sama@2026
```

Change the password from **Account → Password** after the first sign-in.

### What the panel can edit

| Section | Capability |
| --- | --- |
| Dashboard | Enquiries this week, pipeline by status, 14-day chart, quick actions, market coverage, top cities and services |
| Inquiries | Filter by status, full-text search, pagination, per-enquiry notes and status, CSV export, delete |
| Pages | Home page (hero, manifesto, four stat rows, default SEO) and every static page (about, contact, privacy, terms) with rich body copy |
| Insights | Create, edit, publish or unpublish blog posts, with category, cover, excerpt, SEO fields and markdown body |
| Work | Selected-work cards (title, sector, scope, metric, image, order) and client testimonials |
| Services | 44 service lines in 10 categories; edit name, slug, summary, body, deliverables, icon, price from, per-service SEO |
| Categories | Create and edit categories, including process steps and FAQs (`Title | Description` per line) |
| Market area | Add/edit/delete **countries → states/provinces → cities**, bulk-add cities, per-country keyword roles, currency, timezone and market intro |
| Media | Upload images (4 MB, images only), copy paths, delete (removes the file from disk) |
| SEO | Default meta, global keyword roles, bulk-fill missing keywords, sitemap status, technical checklist |
| Settings | Identity, contact details, social profiles, analytics ID, Search Console verification, footer note |
| Account | Name and email, password change, session and deployment notes |

Every write bumps `settings.content_version`, which invalidates the in-process content cache and
the sitemap cache — no restart needed.

## 4. The market-area engine

```
/market-area                                  hub — 7 countries
/market-area/:country                         country page
/market-area/:country/:state                  state page
/market-area/:country/:state/:city            city page
/market-area/:country/:state/:city/:service   city × service landing page
```

Seeded coverage: **7 countries · 92 states · 396 cities · 17,424 generated city × service pages.**

Each country carries its own currency, timezone, working overlap, languages, kickoff note and
keyword roles. Adding a city in the admin instantly creates its hub page and all 44 service pages —
nothing is hard-coded in a template.

Copy is written per location, not swapped: city pages state the region, the neighbouring cities,
the delivery model for that market and the services most often bought there.

## 5. SEO model

Every page renders a title, description, keywords, canonical, Open Graph, Twitter card and JSON-LD
(`Organization`, `Service`, `FAQPage`, `BlogPosting`, `BreadcrumbList`).

Keywords are generated by the requested formula:

```
[Service] + [Role] + [Location]
```

For example, `Website Design Company in New Delhi`, `Website Design Agency New Delhi`,
`Website Design in Delhi`, `Website Design services India`. Roles are per-country (Company, Agency,
Supplier, Importer, Exporter, Manufacturer), so international pages use the vocabulary buyers there
actually search for.

Endpoints:

- `/robots.txt` — allows search engines **and** AI crawlers (GPTBot, ClaudeBot, PerplexityBot, …)
- `/llms.txt` — plain-language citation guidance for language models
- `/sitemap.xml` — index
- `/sitemap-pages.xml`, `/sitemap-services.xml`, `/sitemap-blog.xml`
- `/sitemap-market.xml` — country/state/city hubs
- `/sitemap-market-services-{n}.xml` — chunked city × service URLs

## 7. Security

- Session cookie `sama_sid` — HttpOnly, SameSite=Lax, signed with a scrypt-hashed password store
- CSRF token on every admin POST (including login and logout)
- Login rate limited to 8 attempts / 15 minutes per IP + email
- Inquiry API: honeypot field, 6 requests / hour / IP, server-side validation
- CSP with per-request nonce, no inline scripts without nonce
- `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`
- Uploads restricted to images, 4 MB, randomised filenames
- Admin is `noindex, nofollow` and enforces an auth redirect to `/admin/login?next=…`

## 8. Deployment notes

**cPanel:** the repository ships `app.js` (startup file), `.htaccess` (blocks direct downloads of
the database and source) and a step-by-step Hinglish guide in [`DEPLOY-CPANEL.md`](DEPLOY-CPANEL.md).
Use cPanel → *Setup Node.js App* with Node **22.5+**, application root `samasolution`, startup file
`app.js`. `node_modules` and a pre-seeded database are included in the deployment zip, so no build
step is required.

## 8. Deployment notes

Static assets are served with long-lived caching; HTML is rendered per request. Point a reverse
proxy (nginx/Caddy) at `PORT` and enable TLS. For a true separation of concerns, mount
`src/routes/admin.js` on a second hostname and restrict it by IP allowlist or SSO — the router only
depends on `res.renderPage` and the shared libraries, not on the public routes.

Back up `data/site.db` and `public/uploads/` — those two hold all runtime content.
